# Evaluation protocol

This protocol predicts held-out models' scores on held-out benchmark questions from 50, 100, or 200 observed answers. The primary regime is `strict_unseen_item`: final test-question labels are unavailable for every model during training, probe selection, adaptation, and tuning. It implements the information boundary in §9.1 of [the project discussion](../../doc/EmbedLLM_期末專題選題討論.md). The random-model experiment uses [protocol.json](../../configs/protocol.json); the paired family experiment uses the separately frozen [family_protocol.json](../../configs/family_protocol.json).

The score is performance on the retained historical prompt/category representatives and their recorded binary labels. The release does not preserve all generation settings, evaluator revisions, or scoring-filter identities; singleton structure does not establish uniform evaluation conditions. This score is not an estimate of general intelligence, the complete original benchmark, or a newly queried frontier model's future performance. The method adapts a small evaluator; it does not compress or fine-tune an LLM.

## Data target and inclusion

Pin the Hugging Face source revision, hash downloaded assets, and preserve source model and prompt IDs. The initial candidate sources are MMLU, MedMCQA, MathQA, TruthfulQA, and LogiQA. Candidate sources may expand on raw row structure and documented condition coverage before outcome comparisons. Treat MMLU as one benchmark; its subjects do not each receive another benchmark weight.

The primary target requires a complete raw audit. Retain a prompt only when every retained model has exactly one raw row and the prompt has a single task category/source. Drop agreeing duplicates as well as conflicting duplicates. This rule depends on record structure rather than correctness values. Preserve missingness; neither missing entries nor unresolved conditions become incorrect answers. Freeze the model set, target rule, item mask, benchmark set, and attrition report before fitting competing methods.

This complete-case mask uses held-out models' historical record existence/counts. It does not use their correctness values, but it is still retrospective selection using test-model metadata and can change the estimand or reveal answer availability. It cannot be constructed for a genuinely new model before that model has been evaluated across the candidate pool. Report this limitation and the attrition; do not infer that deployment on a new model will reproduce the same clean support.

The published label tensors remain a separate sensitivity target named `public_tensor`. The full raw audit found that every released tensor cell equals the maximum of its corresponding raw labels, with no missing model/prompt groups at the CSV level. Across all sources it recorded 4,586,288 raw rows, 553,616 duplicate model/prompt cells, and 77,581 cells with conflicting labels. This is an empirical relation between released assets, rather than recovered evidence about upstream evaluation or failure handling. A result on this target describes prediction of the released tensor. It does not establish single-condition answer accuracy. The original repository's router construction uses its own last-row/missing-as-zero rules; this implementation must not inherit those rules.

Report retained and excluded model/item counts, duplicate and missing rates by source, the smallest benchmark, and coverage by lineage when available. If the structural subset is too small, report the limitation or the separate public-tensor experiment; do not quietly change the target after examining performance.

The frozen grouping-v2 selection contains 88 audited models and 22,475 prompt representatives. Before deduplication, 22,624 prompts pass the structural five-source filter; its singleton pattern is identical across all 112 released models, so changing the retained model scope does not alter that particular mask in this release. The representative step removes 149 prompts: 147 MMLU, one MedMCQA, and one LogiQA. Retained counts are LogiQA 650, MMLU 13,841, MathQA 2,985, MedMCQA 4,182, and TruthfulQA 817. The exact source IDs and grouping version are frozen in [the primary selection manifest](../../reports/data_audit/primary_selection.json); their prepared-dataset fingerprint is `d37f4c6eeb850831f0e6ceb439377ad4b434d943b3df51174af0cfa515fad9ba`.

## Models, item groups, and reproducibility

Create one model partition and one benchmark-stratified item-group partition before training. Default proportions are 70% training, 15% validation, and 15% test, with fixed seeds 2718 and 1729. Save both positional indices into the prepared tensors and their source IDs. Optimization/probe seeds are 11, 23, and 37; these runs share the fixed partitions. They measure optimization and acquisition variability, not three independent datasets.

Group underlying questions before splitting. Proven source item IDs take priority; reviewed question/option mappings come next. The current release lacks source item IDs, so grouping version 2 unions matches from normalized full prompts, complete stem/sorted-option keys, and identical complete extracted stems. The stem union keeps known punctuation-only option variants together, and deliberately also groups some generic identical stems with different options. Record the exact extraction and normalization rules and publish the overlap audit. From each detected group in the eligible five-source/audited-model subset, retain exactly one representative: the lowest original source prompt ID, chosen globally even if the group crosses benchmarks. Its retained source/category determines the benchmark for this representative. This metadata-only rule prevents duplicate group weighting and makes k probes mean k distinct detected base groups. Save every retained and dropped source ID. Any analysis retaining all prompt variants must be named separately.

A normalized-text hash supports a claim of disjoint detected groups, not a guarantee of semantic novelty. Heuristic grouping may miss paraphrases or merge contexts that matter. Shared few-shot demonstrations and unresolved near duplicates must be disclosed; they are not independent held-out items. The score target remains the chosen prompt representatives, rather than the complete original benchmark.

Require at least 100 train, 30 validation, and 30 test items in each retained benchmark after grouping. These feasibility thresholds are checked before comparing methods. They ensure a usable instrument, not a precision guarantee. The three budgets require at least 200 eligible probe items and sufficient per-domain capacity for the balanced quota.

Use the same audited-model scope for every experiment. Apply its structural singleton filter once, before making any model split; do not create a larger or easier question subset for individual families. Random held-out models form the main reference experiment. Family blocks come from shared base-weight lineage evidence, with unknown ancestry and unresolved cross-family merges excluded from every partition. Save evidence for each assignment. These conservative blocks may cover a model series; their separation does not establish unrelated pretraining data.

The paired ancestry stress test holds out all six Qwen models as the same unrelated validation block. Its three target cases sample 8 Llama, 6 Mistral, and 3 Yi models deterministically. For each case, choose 40 training models in both conditions. First choose related non-target models R (8, 8, and 6 respectively), then unrelated common models C of size 40 − |R| and unrelated replacements U of size |R|. The family-excluded condition trains on C ∪ U and contains no member of the target family. The relatives-allowed condition trains on C ∪ R. The validation models, target models, item split, and static probes are identical within each pair. Other target-family models remain unused; they never enter the excluded condition. Persist all C/U/R and unused source IDs in each paired manifest.

Select one shared hyperparameter setting per predictor on the mean validation result across both conditions, before scoring their targets. Each condition learns its own training-only decoder and empirical prior. Balanced random is the core matched policy for the ancestry comparison. Adaptive policies can acquire different probes because their trained decoders differ, so that result combines training-composition and acquisition changes. Matching target IDs and training count controls two major confounders but does not isolate a causal ancestry effect; the swapped models also differ in size, tuning, and other characteristics. Show each target block, sample count, and number of relatives. A narrow interval over related model variants does not establish broad cross-family generalization.

The family study uses the original pre-grid hidden width 128, learning rate 0.002, and latent penalty 0.002. It does not inherit the random-model grid winner. This separation matters because some fixed family targets appeared among the random experiment's development models, including Mistral source IDs 44 and 47 in its validation set. The family configuration therefore makes no architecture search from those results. Its dedicated file was created while the main grid was running; the fixed numerical architecture defaults already existed before that grid. Warm-up removal and cold-start checkpoint scoring are documented general training/task-alignment amendments. Each family arm trains fresh structured rank-8 and rank-0 models, and chooses its checkpoint from Qwen validation only. Prior and baseline settings are then jointly selected across both arms on that same Qwen block. Use only balanced random for the family study. Do not interpret its absolute error difference from the primary grid-selected run as a clean family gap; the within-family pair is the controlled comparison.

## Information access

| Stage | Allowed labels | Allowed selection features |
| --- | --- | --- |
| Shared evaluator fitting | Training models × training items | Training-item embeddings and benchmark IDs |
| Checkpoint selection | Validation models' selected training-pool probes; validation models × validation items for cold-start score evaluation | Fixed training-pool balanced probes; validation items for scoring |
| Cold-start tuning | Validation models' selected training-pool probes; validation models × validation items for scoring | Training/probe-pool features for selection |
| Final adaptation | Test models' selected training-pool probes only | Training/probe-pool features for selection |
| Final scoring | Test models × test items, after the lock | Prediction-only test features; never a selector reference |

Final test-item labels are excluded for old models too. Test-model validation labels are unused. Feature preprocessing, priors, and any learned probe representations are fit on training data. Released model embeddings trained on the complete model pool are forbidden initializations. The allowed precomputed text encoder is fixed and checked against source prompt order; any normalization, projection, clustering, or empirical feature scaling is fit on training items.

Code should pass only the allowed subarrays to each stage. Split validators must reject model overlap, item-group overlap, missing benchmark coverage, and known family overlap. Probe selectors receive eligible indices and training-pool features rather than full response matrices. A selected label is revealed only after its prompt is chosen. Predictors within a policy reuse the exact selected source prompt IDs.

Selection uses a training-pool reference distribution. It does not inspect final target embeddings, labels, or target-derived normalization. Prediction-only test-feature caches may be computed separately, but must never reach a selector or affect its reference distribution. A score-aware acquisition extension may estimate uncertainty in per-domain mean scores on that reference pool. It must be described as a proxy for held-out benchmark-score uncertainty, and it must log every chosen prompt, the criterion, and revealed budget. It cannot be described as minimizing the observed test error.

## Adaptation, policies, and baselines

Train each shared decoder from scratch for each optimization seed using only allowed training cells. These independently implemented logistic response models are inspired by EmbedLLM's factorization; they are not faithful reproductions of the paper's architecture. The structured latent combines global, benchmark, and rank-8 residual components; rank 0 is a structural ablation, while neural low rank omits the explicit global/benchmark latent effects. The reference model and rank are fixed before test. Freeze the decoder during cold start, infer only the new model latent, and use an empirical diagonal training-model prior. The implementation uses summed negative log likelihood, so prior precision retains its Bayesian meaning as the budget grows. A regularization number would require rescaling before comparison with a mean-likelihood formulation.

A validation-only pilot showed that training-model item BCE could prefer a checkpoint before useful response interactions were learned. Before any final target scoring, remove the interaction warm-up and select checkpoints for the actual cold-start task. At epoch 1 and then every two epochs, infer validation-model latents from 100 fixed balanced-random support probes and score their validation-item macro MAE. Take the minimum over provisional prior strengths 0.3/1/3 as the checkpoint criterion. Every variant selects its own best epoch. Training-model validation-item BCE remains a diagnostic. The provisional checkpoint prior is not the final reported prior setting.

For the random-model experiment, compare the eight combinations of hidden widths 32/128, learning rates 0.001/0.002, and latent penalties 0.0001/0.002 using seed 11. For each combination, train structured rank 8, rank 0, and neural low-rank variants, then tune each variant's prior over all three budgets. Select one shared configuration by mean final validation macro MAE across all three variants and budgets, rather than giving the main variant its individual winner. The selected configuration is width 128, learning rate 0.001, and latent penalty 0.002; full rankings and per-variant sensitivity remain in [the development decision](../../reports/development/selection.json). Validation performance after this search is a development result and is not an unbiased final estimate. The final experiment uses all three optimization seeds with the selected shared configuration.

Under that shared configuration, neural low rank had the lowest seed-11 validation score among the three variants. Before three-seed validation or final testing, declare `coldstart_neural_lowrank` the practical primary predictor and use its frozen features/prior for both Fisher selectors. Retain all three representations and all matched-predictor comparisons. A later three-seed ranking change does not change this declared primary predictor. The structured extension receives no special advantage from being the proposed architecture; its value remains an empirical comparison with rank 0 and low rank.

Main validation placed the smoothed-mean and KNN optima at their original grid boundaries. Before final testing, make one finite fairness amendment: extend mean smoothing to 0.5/2/5/10/20/50/100, KNN prior weights to 0/1/3/10/30, and final neural adaptation strengths to 0.1/0.3/1/3/10. KNN neighbor counts remain 5/10/20 and temperature 0.1. Add the scalar logit-shift baseline below with the same five adaptation strengths. Keep shared training hyperparameters, provisional checkpoint strengths 0.3/1/3, and the declared primary predictor unchanged. This amendment uses validation only, and does not trigger further grid expansion if a new optimum reaches a boundary. It does not alter the separately frozen family instrument.

After freezing checkpoints, select final prior strength and baseline settings using validation-model macro MAE, averaged over the three budgets and seeds under balanced random probes. Use one selected setting for every acquisition policy. Save the full validation search, including unsuccessful settings. Break exact score ties by stronger regularization and then the simpler model. Early stopping and MAP iteration limits are also fixed before test. The family study retains its original prior strengths 0.3/1/3, mean smoothing 0.5/2/5/10/20, KNN prior weights 0/1/3, and no scalar baseline. For each paired family case, choose those final prior and baseline settings from the mean Qwen validation score across both arms, seeds, and budgets; neither arm tunes on its target models.

The static selection factorial has global random, benchmark-balanced random, global diversity, and benchmark-balanced diversity. Balanced quotas follow one fixed domain order and reallocate exhausted-domain slots deterministically. Sampling is without replacement. Diversity uses the same distance/algorithm globally and within benchmarks. The first 50/100/200 prompts of a shared acquisition order give nested budgets when supported. Static policies use no new-model answers to choose prompts.

The predeclared adaptive extensions are `fisher` and `balanced_fisher`. Both use the declared neural low-rank selector, begin with 10 balanced warm-up probes, and refit the new latent after every revealed answer. Their score-gradient reference uses up to 64 fixed-seed random training-pool items per benchmark, with equal benchmark weighting; it never uses held-out target features. Global Fisher chooses any eligible unused probe, while balanced Fisher obeys the fixed quota schedule. Neither selector reads an unchosen response. Log selector identity, reference IDs, warm-up IDs, every selected ID, acquisition scores, and cumulative revealed labels. The score-aware criterion is a proxy based on the training reference distribution, rather than direct optimization of held-out scores.

Evaluate the training-model benchmark prior, smoothed benchmark and global probe means, question-KNN using the new model's probe labels, and the cold-start decoders. The main experiment also includes scalar logit shift: p[d,a] = sigmoid(b[d] + a), where b[d] is the logit of pooled training-model/training-item benchmark accuracy, clipped to [10⁻⁶, 1 − 10⁻⁶]. Fit each training model's scalar offset by its Bernoulli likelihood with ridge 10⁻⁶, then estimate a scalar empirical prior from those offsets with a standard-deviation floor of 0.2. Infer the new offset by Gaussian-prior MAP using the selected probe labels; its precision is the selected strength divided by the fitted variance. This baseline transfers one global ability change across benchmark-specific difficulty levels. It has no text representation and is not a text-difficulty-matched ablation of the neural decoder.

All answer-dependent baselines share a policy's probe IDs and budget. For a benchmark without probes, the direct benchmark mean uses its training-only prior; the scalar baseline can still transfer its shared ability estimate from other benchmarks. A probe mean drawn by diversity is a heuristic; it is not an unbiased random-sample estimator. A support-to-test distribution change can also affect the random-probe mean. Report this distinction alongside results.

Ordinary model-KNN or item-parameter IRT cannot use old-model test-item answers in this regime. A text-conditioned variant may predict those unavailable responses, but the source of those predictions must be explicit. A fixed-bank experiment may expose old-model answers on all bank items and use proper model-KNN/IRT. It requires a separate manifest and result table labeled `fixed_bank_coldstart`; it tests unseen responses from a new model, rather than globally unseen items. Published fitted parameters or prompt sets that saw our test models are not valid leave-model-out baselines.

## Scores and uncertainty

For model m and benchmark d, compute the true score a[m,d] and predicted score p[m,d] over exactly the same observed test items. Use proportions internally; multiply by 100 for percentage-point displays. Primary macro MAE is the mean of |p[m,d] − a[m,d]| over benchmarks within each model, then over held-out models. Every retained benchmark receives equal weight. The default scorer rejects a model missing an entire benchmark, so missingness cannot silently change its macro denominator.

Also report mean per-model maximum benchmark error, maximum positive overestimate, each benchmark's MAE and signed error, item-weighted benchmark MAE, and the absolute error of the all-item mean. The latter can cancel opposing benchmark errors and cannot replace macro MAE. Report item Brier and log loss, plus benchmark-macro versions. Brier and log loss assess probabilistic predictions; neither alone establishes calibration or benchmark-score interval coverage.

Save per-model, per-benchmark, per-seed records with model/source IDs, budget, policy, predictor, rank, prior strength, target definition, split hash, and selected source prompt IDs. Record fitting time, per-model adaptation time, selection time, and hardware. Compare policies and predictors on paired models, splits, masks, and budgets.

Average each model's metric over seeds before computing the headline point estimate and its 95% percentile bootstrap interval. This estimates seed-averaged method performance, rather than the performance of an ensemble of seed-averaged probabilities. Resample held-out models jointly across compared methods. Where independently audited lineages are available, resample whole lineage groups and retain the model-weighted estimand; otherwise, label model-level intervals as conditional on the observed correlated model pool. Use 10,000 replicates and bootstrap seed 8675309. Suppress a lineage interval for a single-family target case, because it supplies only one lineage unit, and show per-model results. A combined interval over two or three target blocks remains descriptive and weak. Show the number of independent units and per-seed variability. Do not resample millions of model-question cells as independent trials, and do not count seeds as additional models.

Predeclared macro-MAE contrasts are balanced random minus global random, balanced diversity minus balanced random, Fisher minus global random, balanced Fisher minus balanced random, and balanced Fisher minus Fisher. Negative differences favor the first method. Show all budgets and methods, including negative results. Intervals are descriptive and do not provide a family-wise guarantee across the many methods, budgets, and metrics. Later changes or analyses are labeled exploratory.

One predeclared diagnostic permutes revealed responses within each benchmark under fixed balanced-random probes. For each budget, slice the prompt IDs and answers to that budget first, then permute only finite answers within the prefix. Keep probe IDs, domain totals, missing positions, decoder, prior, and inference settings fixed; do not rerun acquisition. Permuting 200 answers and then taking 50 would import unrevealed labels and is forbidden. Apply the same per-model/budget permutation to structured rank 8, rank 0, and neural low rank, and compare each with its original-response prediction. A rank-0 structured latent has constant within-domain response features, so its MAP predictions should be invariant to this permutation even with varying item difficulty. A learned-embedding gain that survives permutation supports a domain/shrinkage explanation rather than item-specific response information. The low-rank control was added before test after it performed well in validation; none of these diagnostics can select the final model. The separate paired family study omits this auxiliary diagnostic.

Routing is optional and secondary. Freeze the candidate pool from training/validation evidence, adapt each candidate under the same probe policy, and route a common held-out question to the highest predicted success probability. Report actual selected-answer quality and regret against a labeled hindsight per-item oracle. Compare with a validation-selected fixed model and report the hindsight-best-fixed reference separately. Total collection budget is candidate_count × probes_per_candidate. The dataset provides no verified current per-query prices, so this experiment makes no cost-efficiency claim. Routing uncertainty must account for shared questions and candidates; the benchmark-score model bootstrap is not automatically a valid routing interval.

## Test lock and interpretation

Before any complete test run, write `artifacts/test_lock.json` containing the source and prepared-data hashes, target rule, grouping audit, model/item split hashes, code revision or source hashes, seeds, policies, budgets, baseline settings, chosen validation hyperparameters, selected checkpoint hashes, and the exact planned contrasts. Save probe IDs for static policies; adaptive policies save their frozen algorithm/configuration and reveal log during execution. The lock records a UTC timestamp and the validation summary that justified selection.

The final test run loads that lock and evaluates all declared methods and seeds. Fixing an implementation error requires documenting the error, its affected results, and a new versioned lock. Changing settings after observing test scores makes subsequent comparisons exploratory. Do not relabel that tuning as validation.

Conclusions remain conditional on the retained sources, historical models, recorded prompt/metric conditions, detection quality of underlying-item groups, and the available lineage evidence. External LLM pretraining contamination is outside this split's control. Failure to beat a simple baseline remains a valid result when the information budget and target are matched.
